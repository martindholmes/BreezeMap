Spike: OpenLayers per-feature setStyle → MapLibre feature-state + expressions

Same three features, same palette, driven by the same runtime state (hidden / normal / selected, plus a category index that drives colour). Left engine reproduces BreezeMap's current imperative styling; right engine reproduces it declaratively. The hard case — directional arrows that OL culls per-segment by pixel length (pixLen > 25) — is handled on the MapLibre side by symbol-placement: line plus collision detection. Zoom both maps out and watch arrows drop on short segments.

Per-feature style function re-evaluated each frame with the current resolution.

MapLibre (target model — setFeatureState + paint expressions)

One source, static layers. Only per-feature state changes at runtime.

FeatureStateCategory (colour)
Translation notes (what this spike proves)
  • Category colour from runtime state. OL reads feature.getProperties().showingCat inside the style fn. MapLibre reads ["feature-state","cat"] in a match expression on paint properties (fill-color, line-color, icon-color, text-color). Live re-colour = map.setFeatureState({source,id},{cat}).
  • Three visual states. OL swaps whole style objects (getCategoryStyle / getSelectedStyle / hiddenStyle). MapLibre keeps one set of layers and switches on ["feature-state","vis"] for colour/width/opacity.
  • Selected halo + raised z. OL uses a magenta stroke + an incrementing zIndex. MapLibre uses a dedicated halo line layer above the base line layer (layer order replaces per-feature z).
  • Icon tinting. OL tints ol.style.Icon via its color. MapLibre needs an SDF image (addImage(..., {sdf:true})) so icon-color can tint it. Done at runtime here from a canvas.
  • Directional arrows (the hard mismatch). OL walks each segment, measures pixel length against the view resolution, and manually places a rotated triangle only when pixLen > 25. MapLibre does this declaratively with a symbol layer, symbol-placement: line, symbol-spacing, and built-in collision detection — arrows that don't fit are dropped automatically. No resolution math in app code.
  • Labels only when selected. OL's selected style adds text. text-field is a layout prop and can't read feature-state, so we keep the field constant and gate visibility via text-opacity (a paint prop). This layout-vs-paint split is the one recurring gotcha.
